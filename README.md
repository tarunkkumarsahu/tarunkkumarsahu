## Selected work

### [EXOCROTEX](https://github.com/tarunkkumarsahu/EXOCROTEX)
**Rust · Tauri · React · SQLite · Ollama**

Experimental cognitive workspace with persistent memory, evidence-linked state, a loopback Rust API, a native Tauri desktop shell and local AI chat. The repository documents what is implemented, what is tested and what is still intentionally not claimed.

### [FreshFusion](https://github.com/tarunkkumarsahu/Fresh-Fusion-)
**FastAPI · React · OpenCV · ESP32 · Ollama**

Multimodal fruit-quality investigation system combining smartphone vision, environmental sensing, relative gas-response analysis, multi-view inspection and evidence validation. The assessment logic is deterministic; the local model is used for explanation rather than making the final decision.

[Live demo](https://fresh-fusion-jet.vercel.app/)

### [AWR-Bot](https://github.com/tarunkkumarsahu/AWR-Bot-)
**ROS 2 · Nav2 · Gazebo · SLAM · LiDAR**

Autonomous warehouse robot prototype for SKU-to-rack mission planning, obstacle-aware navigation, modular pickup/drop workflows and rack-to-packing delivery. The software stack includes a mission manager, Nav2 recovery handling and a Gazebo/RViz demo environment.

### [RAKSHA Grid](https://github.com/tarunkkumarsahu/raksha-grid)
**FastAPI · GIS · routing · incident response**

Disaster-response backend for incident handling, road-state changes, rerouting, shelter allocation and coordination workflows. Development is split between a stable public repository and a more advanced private core before reviewed releases.

### [AgriNexus ProofOS](https://github.com/tarunkkumarsahu/agrinexus-ai)
**Next.js · FastAPI · SQLite · Android scaffold**

Evidence-driven agriculture decision prototype with farm records, scenario comparison, saved decision passports and weather context. Current calculations are explicitly illustrative rather than presented as validated agronomic advice.

### [JARVIS OS](https://github.com/tarunkkumarsahu/Jarvis-OS)
**Python · local AI · tools · memory**

Long-term personal AI systems project exploring model abstraction, memory, tool execution and desktop interaction. It is active early-stage R&D, not presented as a finished autonomous assistant.

## How I build

- **Understand before automating.** AI should accelerate engineering, not replace understanding.
- **Research before implementation.** Existing approaches deserve study before reinvention.
- **Validate before claiming.** A demo, a tested prototype and a production system are different things.
- **Document limitations.** Constraints and failures are part of the engineering record.
- **Ship working artifacts.** Progress should leave behind code, tests, demos or measurable evidence.

> **Researched ≠ Implemented · Implemented ≠ Validated · Demo ≠ Production**
